# SDD-0001：可插拔流媒体引擎集成层

## 状态

Accepted，2026-08-18。

## 问题

现有 Java 项目接入流媒体能力时，业务代码通常直接依赖原生句柄、JNA 回调、特定框架生命周期或远程 HTTP API。引擎替换、测试、升级和资源释放因此变得困难。

## 目标

1. 业务模块只依赖 `streambridge-api`。
2. 引擎实现可以通过显式注册或 `ServiceLoader` 插拔。
3. 框架适配器只管理依赖注入、配置绑定和生命周期，不拥有媒体领域逻辑。
4. Native/JNA 类型不得出现在公共业务 API 中。
5. 启停操作幂等；初始化失败后状态可诊断，已申请资源必须释放。
6. Mock 引擎无需网络和动态库即可覆盖业务测试。
7. 第一方 RuoYi-Vue 适配支持用户提供的 3.9.2 基线。
8. 第一方前端接入包支持用户提供的 RuoYi-Vue3 3.9.2，并只依赖稳定 REST 契约。

## 非目标

- 第一阶段不重新实现 ZLMediaKit。
- 不把 HTTP 客户端、裸 TCP、线程池和 FFmpeg 像素转换等基础设施原语复制进稳定业务 API；它们应作为独立低层插件按实际需求增加。
- 核心模块不提供 Web Controller、数据库表或权限模型。
- 核心模块不自动从互联网下载原生库。

## 用户故事与验收条件

### US-1：纯 Java 集成

开发者只添加 API、Core 和一个引擎插件，即可创建、启动和关闭引擎。

- 未安装插件时给出包含插件 ID 的明确异常。
- 重复注册同一插件 ID 时失败，不允许静默覆盖。
- 关闭 `StreamBridge` 时，其创建的所有引擎均被关闭。

### US-2：可测试业务

开发者使用 Mock 引擎进行推流代理业务测试。

- `pull` 后 `listStreams` 可观察到目标流。
- 关闭句柄或调用 `closeStream` 后流消失。
- 状态变化和流变化产生类型安全事件。

### US-3：ZLMediaKit 嵌入式运行

开发者显式提供动态库名称或绝对路径后启动嵌入式引擎。

- 没有动态库时抛出可定位的 `StreamBridgeException`。
- 可配置 HTTP、RTSP、RTMP 监听端口；负数表示不启动对应服务。
- 应用关闭时调用上游公开 C ABI `mk_stop_all_server`。

### US-4：RuoYi-Vue 集成

RuoYi-Vue 应用添加 starter 和引擎依赖后，通过配置选择引擎。

- starter 不要求修改 RuoYi 启动类。
- 容器生命周期驱动引擎启停。
- 适配门面不自动暴露未授权的管理接口。

### US-5：RuoYi-Vue3 前端

开发者复制 API 文件、页面和菜单 SQL 后可以查看引擎状态与流列表。

- 页面沿用若依 `request` 封装和动态菜单机制。
- 页面不展示 Native 库路径、密码或媒体源凭证。
- 前后端通过文档化 DTO 交互，不序列化 JNA 或引擎内部对象。

## 版本路线

- M1：插件内核、Mock 引擎、ZLM 生命周期、RuoYi starter。
- M2（已实现）：流查询/关闭、拉推代理、全局流事件和统一错误模型。
- M3（已实现）：录制、WebRTC、RTP/GB28181、媒体输入、播放器与帧回调。
- M4：远程 ZLMediaKit HTTP 引擎与兼容性矩阵。
